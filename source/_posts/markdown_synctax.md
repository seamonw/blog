写博客、记笔记时，Markdown 足够覆盖大部分排版需求。下面按使用频率整理一份常用语法，示例都可以直接复制。

Hexo 使用 [GFM](https://github.github.com/gfm/) 风格渲染，和 GitHub 上看到的效果基本一致。正文标题建议从二级开始写，一级标题由文章的 `title` 生成。

## 标题

`#` 后面加空格，层级从 1 到 6：

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

## 段落与换行

空一行会开始新段落。同一段里如果只敲回车，渲染后通常仍会连在一起。

需要强制换行时，在行尾加两个空格再回车，或直接拆成两段。

## 强调

| 效果 | 写法 | 渲染 |
| --- | --- | --- |
| 斜体 | `*斜体*` 或 `_斜体_` | *斜体* |
| 粗体 | `**粗体**` 或 `__粗体__` | **粗体** |
| 粗斜体 | `***粗斜体***` | ***粗斜体*** |
| 删除线 | `~~删除线~~` | ~~删除线~~ |

行内代码用反引号包起来，例如 `` `vector` `` 会渲染成 `vector`。

## 列表

无序列表用 `-`、`*` 或 `+`：

```markdown
- 编译
- 链接
  - 静态链接
  - 动态链接
- 运行
```

- 编译
- 链接
  - 静态链接
  - 动态链接
- 运行

有序列表用数字加点，数字本身不要求连续，渲染时会自动编号：

```markdown
1. 打开终端
2. 执行 `hexo n "文章标题"`
3. 执行 `hexo s` 预览
```

1. 打开终端
2. 执行 `hexo n "文章标题"`
3. 执行 `hexo s` 预览

任务列表（勾选框）适合写待办：

```markdown
- [x] 写完语法说明
- [ ] 配一张配图
- [ ] 发布到 GitHub Pages
```

- [x] 写完语法说明
- [ ] 配一张配图
- [ ] 发布到 GitHub Pages

## 链接与图片

行内链接：

```markdown
[Hexo 文档](https://hexo.io/zh-cn/docs/)
[相对链接](/archives/)
```

[Hexo 文档](https://hexo.io/zh-cn/docs/)

引用式链接适合同一地址反复出现时使用：

```markdown
先看 [官方文档][hexo]，再对照 [主题说明][next]。

[hexo]: https://hexo.io/zh-cn/docs/
[next]: https://theme-next.js.org/
```

自动链接可以直接包一层尖括号：<https://seamonw.github.io/blog/>

图片语法和链接类似，只是前面多一个 `!`。图片文件建议放在 `source/images/`，正文里用站点根路径引用：

```markdown
![迁移时需要复制的文件](/images/blog_mv_file.png)
```

不需要图片说明时，方括号可以留空：`![](/images/blog_mv_file.png)`。Hexo 会按站点 `root` 补上前缀，部署在 `/blog/` 时实际地址是 `/blog/images/blog_mv_file.png`。

## 代码

行内代码用一对反引号。代码里本身有反引号时，外边改用两个：

```markdown
`` 这里面可以写 `code` ``
```

代码块用三反引号，第一行可以写语言名，方便高亮。下面是 C++ 示例：

```cpp
std::vector<int> v;
std::sort(v.begin(), v.end());
```

再给一个带行号场景更常见的片段：

```cpp
#include <algorithm>
#include <vector>

int main() {
  std::vector<int> v{3, 1, 2};
  std::sort(v.begin(), v.end());
  return 0;
}
```

在文章里演示 Markdown 源码时，外层用四个反引号包住内层的三个反引号，否则会提前结束代码块。

## 引用

`>` 后面跟空格。多层引用可以叠多个 `>`：

```markdown
> Markdown 不是 Word，而是纯文本。
>
> > 先把结构写清楚，再考虑样式。
```

> Markdown 不是 Word，而是纯文本。
>
> > 先把结构写清楚，再考虑样式。

引用里可以继续写列表、代码和链接。

## 表格

表头和分隔行至少要三元组，对齐用冒号控制：

```markdown
| 语法 | 说明 | 是否常用 |
| :--- | :---: | ---: |
| 标题 | 划分章节 | 高 |
| 代码块 | 贴示例 | 高 |
| 表格 | 对比项 | 中 |
```

| 语法 | 说明 | 是否常用 |
| :--- | :---: | ---: |
| 标题 | 划分章节 | 高 |
| 代码块 | 贴示例 | 高 |
| 表格 | 对比项 | 中 |

单元格里可以用行内代码和强调，但不适合再嵌套复杂表格。

## 分割线

单独一行写三个及以上的 `*`、`-` 或 `_`：

```markdown
---
```

---

前后都要空一行，避免被解析成标题或列表。

## 转义

不想让某个符号生效时，前面加反斜杠：

```markdown
\*不是斜体\*
\# 不是标题
```

\*不是斜体\*

常见需要转义的符号：`\` `` ` `` `*` `_` `{` `}` `[` `]` `(` `)` `#` `+` `-` `.` `!` `|`

## 在 Hexo 里写文章时的习惯

1. 元数据写在文件开头的 YAML 里，至少包含 `title`、`date`，分类和标签按需添加。
2. 新建文章用 `hexo new "标题"`，文件会出现在 `source/_posts/`。
3. 本地预览用 `hexo server`，确认无误后再推到 `main`，GitHub Actions 会自动发布。
4. 正文里的站内链接写成 `/archives/`、`/images/...` 这种站点内路径即可，Hexo 会按 `root` 补前缀。当前站点发布后，浏览器里看到的是 `/blog/archives/`。

把结构写清楚，代码和链接补完整，一篇技术笔记通常就够用了。更冷门的扩展语法（脚注、数学公式、图表）可以等真正用到时再加。
